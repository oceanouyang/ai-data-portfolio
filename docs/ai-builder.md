# AI Builder | AI 产品能力与项目实践

面向偏 AI 产品经理的 AI Builder 岗位，我的实践重点是定义用户问题、设计产品流程、利用 AI 协作推进实现，以及检查用户最终拿到的结果。下面三个项目分别展示游戏产品交付、本地模型使用体验和知识工具治理，补充案例展示数据分析与评测能力。

公开材料包含已完成阶段的项目说明、精选实现规则和可运行骨架。游戏中的 AI 用于开发过程；模型服务集成由推理工作站项目展示。本人主要负责需求、规则、体验取舍与验收，主要代码由 AI 辅助实现。

## 1. AI 协作开发离线刷宝 ARPG

**交付物：Windows 玩家测试版、测试 ZIP、界面修复与验收记录。**

**用户与问题：** 玩家需要从营地进入地图，通过战斗获得装备与材料，再制作、换装并继续挑战。战斗、背包与存档必须连贯，关键操作不能被界面遮挡。

**产品职责：** 我定义玩法循环，把需求拆为战斗、技能、背包、制作、天赋和存档规则，确定体验取舍与验收方向，利用 AI 推进实现、问题诊断和迭代。

| 具体问题 | 实现与验收重点 |
| --- | --- |
| 制作扣材与奖励结算必须一致 | 检查一次结算、失败恢复和旧快照保护；公开骨架可运行这些规则 |
| 窄窗口和动态内容导致界面遮挡 | 调整 HUD、装备、天赋与制作布局，按五种窗口尺寸检查 |
| 开发环境通过后仍需检查玩家拿到的包 | 检查导出包内容、隔离双角色存档、原生启动与 ZIP 散列 |

**已完成阶段的证据：** 2026-10-06 保存的记录包含 135 个布局样本无几何诊断、14 份定向回归及内容检查退出码为 0、实际导出包 62 个物品与 20 个技能可见，以及两次隔离启动通过。这些是当时玩家测试版的历史结果，范围限于该版本和有限界面状态。

**体现的能力：** 将玩法设想转化为需求与系统规则，组织 AI 迭代，关注界面审美与操作体验，并核对玩家收到的实际发布包。当前证据支持测试版交付与有限体验验收。

## 2. 本地 AI 推理工作站

**阶段成果：控制器与模型路由实现、容量调优及检索验收记录。**

**用户与问题：** 本地模型使用者需要选中预期模型、输入较长材料并得到可用回答。界面显示与实际后端不一致、容量不足或检索错误，都会影响这条使用流程。

**产品职责：** 我确定部署需求、验收条件和容量取舍，审核诊断与测试记录；AI 辅助实现控制器、模型路由和测试。验收分别关注能否运行、结果是否正确、速度与资源是否可接受。

| 具体问题 | 实现与验收重点 |
| --- | --- |
| 客户端配置与实际后端可能不一致 | 串联进程身份、启动参数、模型清单和客户端期望，区分不可用与模型不匹配 |
| 长输入、输出预算和并发共同占用容量 | 同时核对上下文总预算、共享 KV 与显存余量，保留不合格候选 |
| 接受请求不等于回答正确 | 分别检查冷输入检索、生成速度、显存采样和部署散列 |

**已完成阶段的证据：** 保存的调优记录包含冷输入校准、分散检索、引擎事件、显存采样及部署文件核对。另有既有运行时夹具失败，故结论限于记录覆盖的部署与调优阶段。

**体现的能力：** 理解模型能力与资源约束，把“能接入模型”细化为路由正确、容量可用和回答质量等条件，并据此讨论产品范围与使用体验。公开示例只检查运行契约，历史服务测量与合成输入分开说明。

## 3. 知识库与规则同步工具

**阶段成果：来源注册、允许目标校验、事务回退与冲突保护实现。**

**用户与问题：** 多个 AI 工具共用知识与规则副本时，更新容易覆盖用户修改、失去依据，或让不同工具的行为发生漂移。

**产品职责：** 我定义来源保护、允许修改范围和冲突停止规则，审核同步结果；AI 辅助实现事务脚本、同步逻辑和范围测试。流程需要明确哪些内容可改、什么时候停止、失败后如何恢复。

| 具体问题 | 实现与验收重点 |
| --- | --- |
| 材料来自多个项目，摘要容易失去依据 | 动态读取来源注册表，保留来源、日期与处理范围 |
| 自动更新可能修改不应触及的文件 | 预览、快照、允许目标校验和前后散列比较，验证失败后回退 |
| 预览后源文件或目标副本发生变化 | 检查漂移并停止旧计划；范围选择与内容校验共同生效 |

**已完成阶段的证据：** 已核对事务脚本的范围检查与回退路径；已有 Harness 测试覆盖未选文件、空选择、未知目标、目标漂移和预览后来源变化。公开骨架在内存中演示受限更新与异常恢复。

**体现的能力：** 设计用户可控的自动化流程，把来源、权限、冲突和恢复条件纳入需求与验收。

## 可运行示例与实现细节

Python 3.10+，在仓库根目录执行。示例使用标准库与合成输入，无需模型服务或额外依赖：

```text
python -B projects/05-game/src/game_rules.py
python -B projects/02-runtime/src/runtime_contract.py
python -B projects/03-governance/src/scoped_update.py
```

| 示例 | 成功输出包含 | 演示范围 |
| --- | --- | --- |
| 游戏规则 | `craft_once`、`validation_rollback`、`stale_snapshot_rejected` 为 `true`，`layout_checks` 为 `8` | 内存制作事务、旧快照拒绝和布局边界 |
| 模型运行契约 | `synthetic` 为 `true`，`checks` 为 `6` | 正常配置及五类后端或容量错误 |
| 受限同步 | `disk_writes` 为 `0`，列出范围拒绝、回退、更新和漂移拒绝 | 内存受限更新，不操作真实知识库 |

这些代码是作品集制作时独立重写的演示骨架。完整原工程与玩家测试包保留在本地；当前公开入口是项目文档和规则演示。
